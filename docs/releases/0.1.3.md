This release adds GitHub update checking and in-app portable updates.

## New

- **Setup > Updates** shows the installed version, a manual **Check GitHub** button, release links, download progress and **Restart & update**.
- An optional check on launch runs in the background. Available updates highlight Setup; audio is not interrupted by checking or downloading.
- Only newer stable versions from this repository are offered. Downloads require valid sizes, official release URLs, matching SHA-256 manifest/GitHub digests and a Windows x64 executable header.
- Restart saves settings, restores/stops audio, waits for the old process to exit and replaces the same EXE in place. The new version starts with processing stopped.
- A failed launch or exit before the first UI frame restores and relaunches the previous EXE. A slow but still-running new process is left alone with its backup retained.

## Install this version

**0.1.2 has no updater: download 0.1.3 manually once.** Use the Windows x64 ZIP, extract it and run `sound-lock.exe`. The ZIP contains README and the MIT license; a standalone EXE and SHA256SUMS are also available. Your existing settings are kept.

For future versions, use **Setup > Updates > Download update > Restart & update**. Keep the portable app in a writable folder. Updates do not request administrator access, install drivers or resume processing automatically. The build is unsigned; update trust relies on HTTPS and this GitHub repository. Recovery files are retained beside the app if an update cannot be completed.

45 standard tests pass. Native helper tests replace/restart only temporary fixture EXEs and verify failed-startup rollback; the same checks run in Windows CI before publication. The public GitHub download/checksum flow was also exercised without installing the downloaded release. Live VB-CABLE/browser playback and a real future-version upgrade during playback remain manual checks.
