# Validation — 2026-10-30

Environment: Windows x64, Rust 1.96.1, Cargo 1.96.1. No virtual audio cable was installed during this work.

## Completed

- `cargo fmt --all -- --check`: passed.
- `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`: passed.
- `cargo test --workspace --locked`: **53 passed**, including 11 DSP, 7 audio/native-control, 11 browser-routing/ABI/journal, 11 updater checks, 4 package-handling, 6 popup/settings UI checks and 1 settings preference check and 2 geometry/focus checks. Five environment-dependent tests are ignored by default; the three updater-specific opt-in checks were also run successfully.
- `cargo test --locked update::tests::official_github_release_download_verifies_without_installing -- --ignored`: passed against the actual public GitHub release. Metadata, official asset paths, expected sizes, SHA256SUMS, GitHub asset digests and the downloaded Windows x64 EXE were checked. The downloaded EXE was never executed or installed.
- With `SOUND_LOCK_TEST_EXE` pointing at the final built 0.1.4 release, `cargo test --locked update::install::tests::native_helper_ -- --ignored`: **2 passed**. The real helper held a validated parent process, waited for it to exit, replaced a temporary fixture EXE, relaunched it and observed its startup receipt. A broken fixture exited before acknowledgment; the helper restored the original bytes and relaunched the previous fixture. Both cases used paths containing Unicode, punctuation and spaces. No running Sound Lock, user settings, drivers or audio routes were touched. Windows CI now runs the same checks after its release build.
- Offline updater checks cover numeric SemVer ordering/no downgrades, stable published release requirements, asset uniqueness/URL/size validation, checksum ambiguity/corruption, x64 PE validation, plan path/schema validation, PID identity, atomic backup/rollback and cleanup that preserves unknown files. Available/downloading/ready/error UI states fit the Settings window.
- `cargo test --locked routing::windows::tests::real_policy_roundtrip_restores_own_process_preferences -- --ignored`: passed on the actual Windows per-app audio policy. An unstarted, silent audio stream registers only the test executable; all three output-role preferences were read, changed to an explicit endpoint, read back, restored and verified. No browser or system-default route was changed. Before registering the test session, Windows returned E_INVALIDARG; production discovery therefore only routes/restores processes with registered audio sessions.
- Transactional routing tests cover per-role/Follow-default restoration, partial-change rollback, journal-write failure preventing mutation, new browser children retaining the baseline, browser closure/restart recovery, executable-path/PID isolation, old manual-cable migration, disconnected outputs/default-cable fallback, restoration retry, device-ID conversion and exclusive/atomic journal storage. The journal replacement test needs normal Windows filesystem access; sandboxed replacement initially returned Access denied, and the unrestricted test passed.
- `cargo test --locked driver::tests::official_package_prepares_without_installation -- --ignored`: passed. The actual official Pack 45 archive was downloaded through the app's HTTPS client, checksum-checked, fully extracted and its x64 setup signature verified through Windows. **The installer was not launched and no driver was installed.**
- Release 0.1.4 builds successfully with `cargo build --release --locked --target-dir .local/build-0.1.4`. A separate output directory preserves any running earlier executable.
- Native UI Start/Stop smoke check on the existing headset endpoint: processing started, the meter displayed real input (approximately −46 dBFS), and Stop returned to idle without an error.
- The user confirmed that **Hide > tray menu > Open Sound Lock** now reopens the window correctly in the release build.
- The quick popup is **368 × 304** logical pixels; Settings is 460 wide and resizes to its content (capped at 462 high). Neither uses a scrolling container. Headless egui checks cover both audio paths, long endpoint names, all Settings pages and populated update states. The real settings controls receive no input beneath a modal, the backdrop is dimmed, the dialog border is rendered, and Escape restores input.
- Native preview tests passed for both normal and quiet startup using the actual installed tray callbacks. They observed native visibility, icon toggle, focus-loss dismissal, separate Settings, minimize/restore, close-to-tray, background profile commands without showing windows, reopening after both windows were hidden, and Quit while hidden. Quiet startup covered 12 steps; normal startup covered 11. All audio endpoints/settings were simulated. Reproduction: `scripts/test-tray.ps1` on an interactive Windows desktop.
- Framebuffer PNGs of the popup, Audio, Updates and the dimmed detail dialog were visually inspected. The dialog has a distinct border/shadow, and the final popup has no unused lower region. A QA-only capture failure during a minimized-window test was traced to an empty capture-path environment variable; empty paths are now ignored and minimized captures skipped. The native tray test then passed. Production omits capture code.
- The **actual published 0.1.3 update helper** installed and launched the new 0.1.4 GUI in a private temporary preview directory. The popup rendered, acknowledged its first UI frame, removed the old helper/backup and exited normally after an own-window capture. The target contained the new bytes afterward. This verifies installer-helper receipt compatibility with the new hidden-root/deferred-popup lifecycle; no real endpoint or user settings were accessed. It does not establish old-client discovery of the renamed asset: the user chose no legacy alias, so 0.1.3-to-0.1.4 is a manual upgrade.
- Core Audio read-only probe available through `--probe-system`; each probe initializes COM on its own worker thread.
- `--probe-routing` activated the native policy successfully. No browser audio processes were registered at the time of the probe. The device list still had no VB-CABLE endpoint; no driver was installed by these changes.
- Offline synthetic demo, Night profile at 200%: input peak **−0.45 dBFS**, output peak **−3.00 dBFS**; quiet-scene RMS **−38.77 → −20.87 dBFS**. Generated audio was not played automatically.

## Not yet verified

- End-to-end PCM bridge listening on two physical outputs, prolonged movie playback, Bluetooth reconnects, device disconnect recovery and CPU/latency measurements remain manual checks.
- Baseline volume restoration is implemented and native Start/Stop worked; actual attenuation followed by restoration, including external keyboard/mixer changes, still needs a controlled audio test.
- The elevated vendor installer, its UAC cancellation flow, restart and full VB-CABLE audio route were not exercised on this machine. Those are explicit user-operated setup steps, not automated checks.
- End-to-end automatic routing of real Chrome/Edge/Firefox audio, including browser restarts and Quit during playback, remains a manual check. The native own-process API roundtrip and simulated transaction tests do not establish browser-specific live migration behavior. A browser with no audio session must play audio for pending recovery to complete while Sound Lock is open. Force-kill recovery requires relaunching Sound Lock; there is no watchdog after Quit.
- A real future-version upgrade while audio is playing, antivirus interference, protected application folders and power loss during replacement remain manual checks. Native GUI startup/receipt compatibility was verified with simulated endpoints; the complete real-audio handoff is still unverified. 0.1.3 is updater-enabled but cannot discover 0.1.4's canonical asset name, so this transition is manual. Future canonical assets are supported by the new updater.
- The previous release's Windows CI passed on Rust 1.99.1. Version 0.1.4 also runs the Windows workflow, all-feature compilation and native updater fixture checks before publication. Physical mixed-DPI monitor switching remains manual; unit geometry tests cover four taskbar edges, negative coordinates and 100–200% scale.

System limiter is reactive endpoint attenuation, not a hard sample-peak ceiling. The DSP limiter's sample-peak ceiling applies only to audio routed through the PCM bridge.
